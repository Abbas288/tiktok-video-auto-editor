# #62 — SYSTEM: Systemet ska verifiera och driftsätta appen via CI/CD

Systemet ska ha en automatiserad CI/CD-pipeline så att kodkvaliteten verifieras vid varje förändring och appen kan driftsättas till produktion på Cumulus på ett säkert sätt. Just nu kräver kvalitetssäkring och driftsättning flera manuella steg. Det ökar risken att tester glöms bort, att trasig kod når `main`, eller att deployment sker på ett inkonsekvent sätt. För att minska den risken ska projektet automatisera linting, TypeScript-kontroll, tester, Docker-build och deploymentflöde.

## Acceptanskriterier

- [x] Pipelinen körs automatiskt vid varje Merge Request.
- [x] Verify-steget kör linting, TypeScript-kontroll och automatiska tester.
- [x] Om verifieringen misslyckas ska pipelinen misslyckas tydligt.
- [x] Vid merge till `main` kan appen byggas som en Docker-image.
- [x] Docker-imagen publiceras till GitLab Container Registry.
- [x] Deployment-steget kan driftsätta aktuell image till Cumulus via SSH och Docker Compose.
- [x] Projektet innehåller nödvändiga filer för webbdeployment: `Dockerfile`, `docker-compose.yml` och `nginx.conf`.
- [x] Secrets och serveruppgifter ligger i GitLab CI/CD-variabler och hårdkodas inte i repot.
